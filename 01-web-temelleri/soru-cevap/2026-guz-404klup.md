## Soru 1 — İstemci-Sunucu Modeli

**Soru:** Bir web tarayıcısına `https://developer.mozilla.org` yazdığınızda arka planda hangi adımlar gerçekleşir? Adım adım açıklayın.

**Cevap:**

1. **DNS Sorgusu:** Tarayıcı, `developer.mozilla.org` alan adını DNS sunucusuna sorarak gerçek IP adresini öğrenir (örn. `63.245.215.20`).
2. **TCP/IP Bağlantısı:** Tarayıcı ile sunucu arasında TCP bağlantısı kurulur (3-way handshake).
3. **HTTP/HTTPS İsteği:** Tarayıcı sunucuya `GET /en-US/ HTTP/2` isteği gönderir.
4. **Sunucu Yanıtı:** Sunucu `200 OK` yanıtı ile birlikte HTML dosyasını paketler halinde gönderir.
5. **HTML Ayrıştırma:** Tarayıcı HTML'i alır, DOM ağacını oluşturur.
6. **Kaynakların Yüklenmesi:** CSS, JS ve resim dosyaları için ek HTTP istekleri gönderilir.
7. **Render:** CSS ve DOM birleştirilerek render tree oluşturulur; sayfa ekranda gösterilir (painting).

## Soru 2 — HTTP Durum Kodları

**Soru:** Aşağıdaki HTTP durum kodlarının ne anlama geldiğini ve hangi durumlarda karşılaşıldığını açıklayın: 200, 301, 404, 403, 500.

**Cevap:**

| Kod | Anlam | Ne Zaman? |
|-----|-------|-----------|
| `200 OK` | İstek başarılı | Sayfa normal yüklendiğinde |
| `301 Moved Permanently` | Kalıcı yönlendirme | Sayfa farklı URL'ye taşındığında |
| `403 Forbidden` | Erişim yasak | Kullanıcının izni olmadığında |
| `404 Not Found` | Bulunamadı | URL yanlışsa veya sayfa silindiyse |
| `500 Internal Server Error` | Sunucu hatası | Sunucu tarafında bir hata oluştuğunda |

## Soru 3 — DNS Nedir?

**Soru:** DNS (Domain Name System) nedir ve neden gereklidir? Olmasa ne olurdu?

**Cevap:**

DNS, alan adlarını (örn. `google.com`) IP adreslerine (örn. `142.250.185.46`) çeviren bir sistem olarak internette bir "telefon rehberi" görevi görür.

DNS olmadan:
- Her web sitesine gitmek için IP adresini ezberlemek gerekirdi.
- `216.58.214.78` gibi adresleri hatırlamak imkânsız olurdu.
- İnternet, teknik bilgisi olmayan kullanıcılar için erişilemez hale gelirdi.

## Soru 4 — Web Standartları Neden Önemlidir?

**Soru:** Web standartlarının "açık" (open) olması ne anlama gelir? Bu özellik olmasaydı web nasıl olurdu?

**Cevap:**

"Açık" olması şu anlama gelir:
- Web teknolojileri patent/lisans engeli olmadan ücretsiz kullanılabilir.
- Herkes standart oluşturma sürecine katkıda bulunabilir.
- Hiçbir tek şirket web teknolojilerini kontrol edemez.

Olmasa:
- Büyük şirketler kendi tescilli tarayıcı teknolojilerini geliştirirdi.
- Web siteleri yalnızca belirli tarayıcılarda çalışırdı (uyumsuzluk).
- Web geliştirmek pahalı ve lisans gerektiren bir süreç olurdu.
- İnternet, açık bir kamusal kaynak olmaktan çıkar, ticari bir ürüne dönüşürdü.

## Soru 5 — Uygulamadan: Hata Yönetimi

**Soru:** Aşağıdaki JavaScript kodunda ne tür bir "soft skill" uygulaması görmekteyiz? Kodun `onerror` satırı olmadan nasıl bir sorun çıkabilirdi?

```javascript
kart.innerHTML = `
    <img src="${secilenKisi.foto}" alt="${secilenKisi.isim}"
         onerror="this.src='https://ui-avatars.com/api/?name=${secilenKisi.isim}&background=00a8ff&color=fff&size=128';">
    <h3>${secilenKisi.isim}</h3>
    <p class="rol">${secilenKisi.rol}</p>
`;
```

**Cevap:**

Bu kodda **hata toleransı (graceful degradation)** / **savunmacı programlama (defensive programming)** uygulaması görülmektedir — bu bir **soft skill** olan "öngörülü düşünme"nin kod yansımasıdır.

`onerror` olmadan:
- Resim dosyası bulunamazsa (yanlış uzantı, dosya eksik, vb.) kırık bir resim simgesi (⛔) görünürdü.
- Kullanıcı deneyimi bozulurdu.
- Sistem hata mesajı göstermez ama kullanıcı "bu site çalışmıyor" izlenimine kapılırdı.

`onerror` ile:
- Resim bulunamazsa otomatik olarak isimden avatar üretilir (UI Avatars API).
- Kullanıcı hiçbir zaman kırık resim görmez.
- Sistem "sessizce" kurtarır — bu profesyonel yazılım geliştirmede kritik bir kalite göstergesidir.

**Sonuç:** İyi bir web geliştiricisi yalnızca "çalışan" kod değil, "başarısızlık durumunda da çalışan" (fail-safe) kod yazar.
